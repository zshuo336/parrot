# Parrot 使用者指南：从第一个 Actor 到 Websearch

这套中文文档面向第一次接触 Parrot 的开发者。主线是仓库内真实的 `apps/websearch` 应用：先运行一个受控的小网站，再理解 Rust、Erlang、Python/Ray、Scala/Akka 如何通过 Parrot 组成搜索系统，最后学习持久化、重启、部署和扩展。

文档依据当前源码编写，本次核对日期为 2026-11-19。本文档集的编写不代表这里列出的集成测试已经在你的机器执行通过。软件版本、依赖可用性、磁盘语义和网络条件仍需按章节验证。

## 你将实际学会什么

- 定义带结果类型的消息，创建 Actor，通过引用请求业务结果。
- 区分运行时引擎、网关、应用组件、制品、远程引用和逻辑接线。
- 把业务边界设计为消息协议，让语言和运行时独立演进。
- 使用清单描述拓扑，同时理解装配器为何仍需要具体的业务宿主。
- 区分入队、内存处理、持久化确认和本地任务完成，设计可重放流程。
- 从页面、索引、进程和磁盘四个层面验证真实运行，而不是只看“启动成功”。

## 本书使用约定

所有命令默认从仓库根目录执行，除非明确写出别的目录。`/absolute/...`、`APP_IP`、`user@host` 等是需要替换的占位符。独立终端需要分别激活同一个 Python 虚拟环境。

示例中的 `--insecure-development` 是明确选择未认证的开发网络形态，适用于受控实验网络；它不提供 TLS、身份认证或租户隔离。它不是“提高兼容性”的通用参数，不应被当成生产安全配置。

本书中的“落盘”指应用执行并成功确认对应的文件同步流程；不承诺在任意硬件、文件系统或断电条件下自动满足所有数据库级保障。“恢复”指本示例实现的日志和完整快照恢复，不等于分布式共识、任意节点接管或全局 exactly-once。
