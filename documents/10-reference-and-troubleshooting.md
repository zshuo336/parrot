# 10 命令行、接口与排障参考

## 1. 原始 CLI 形式

```text
websearch [HTTP(S)-seed ...] [erl=IP:PORT] [ray=IP:PORT] [jvm=IP:PORT]
```

权威帮助由当前二进制输出：

```bash
./target/release/websearch --help
```

一般把选项放在 `--` 之前，把 seed 放在其后。单值选项重复通常被拒绝；`--crawl-origin` 可重复提供不同 origin。不要假设 shell 工具的“最后一个值生效”约定在这里也成立。

## 2. 抓取与网页参数

- `--pages N`：最大抓取尝试，默认 50000，必须大于零；失败也消耗。
- `--sites N`：成功 host/port 目标，默认 100，必须大于零。
- `--maxdepth N`：链接深度，默认 10，范围 0 到 65535；0 用于限制在种子层。
- `--crawl-origin URL`：允许的精确 scheme/host/有效端口，可重复。显式 IP 可授权私网目标，域名仍受地址检查。
- `--port N`：Web 服务端口，默认 8080；0 请求 OS 分配，范围受 u16 限制。
- seed：合法 HTTP(S) URL，不应携带用户名密码。`--` 后都按 seed 解析。

未给 seed 时，普通模式使用内置种子；队列耗尽且目标未达成时也可能回填。origin 模式以列出的根为默认 seed，并禁用内置回填。

Web 显式端口被占用时会尝试后续有限候选，最多二十个偏移；接近端口上界时不会溢出回绕。全部不可用则失败。始终访问应用实际报告的端口。

当前原始 Web listener 绑定 `0.0.0.0`，即所有 IPv4 接口。READY 显示 loopback 访问地址不表示服务只监听 loopback。本机实验应在受控环境运行；需要限制暴露时使用系统防火墙、网络隔离或受控端口映射。

## 3. 数据与服务参数

- `--data DIR`：Rust journal/identity 目录，原始 CLI 默认 `./data`。启动器另有每次独立目录策略。
- `--index-data DIR`：JVM 上的绝对索引数据根，会持久化用于后续运行。
- `--keep`：保留已有索引与发现集合，恢复并继续工作。
- `--serve-only`：隐含 keep，不抓取，拒绝 seed。

没有 keep/serve-only 的普通抓取会创建新索引状态。不要把 data 路径一致误解为所有启动都会自动保留历史。

## 4. 网络与远端制品参数

- `erl=IP:PORT`、`ray=IP:PORT`、`jvm=IP:PORT`：direct 网关地址，具体 IP、非零端口，IPv6 使用方括号。
- `--bind IP:PORT`：应用监听等待反拨，支持端口 0。跨机监听地址和网关连接地址必须可达。
- `--wait N`：注册期限秒数，默认 60，范围 1 到 86400。
- `--node-root DIR`：远端网关看到的绝对业务制品根。
- `--insecure-development`：显式允许未认证远端开发模式，不提供 TLS 或认证。

默认 direct 地址在原始应用中为本机 Erlang 19871、Ray 19873、JVM 19872。监督启动器会分配自己的动态端口，因此调试启动器时不要强行访问这些固定默认值。

## 5. 清单与检查参数

- `--manifest FILE`：启用本应用内置的清单宿主。
- `--runtime-root DIR`：清单模式的本机网关运行资源根，要求绝对路径；安装宿主包可自动发现。
- `--gateway-process-limit N`：清单宿主拥有的网关/编译器进程组上限，默认 64。
- `--validate-only`：输入验证后退出，不启动真实业务、不修改存储或绑定服务端口。
- `--help` / `-h`：显示帮助。

runtime-root、gateway-process-limit 有适用模式限制，manifest 不允许混用手工 direct 地址或 node-root。具体组合以 CLI 错误为准，不要通过删校验来让配置“被接受”。

## 6. HTTP 入口

`/`：搜索首页与导航。页面由 Rust 生成。

`/search?q=关键词&p=1`：返回 HTML 搜索结果。p 是从 1 开始的结果页，限制在 1 到 10，每页十条。空查询重定向首页。

`/stats`：返回 JVM 健康统计 JSON。正常 200，远端或协议失败可返回 502。它不提供整个应用所有组件的统一健康证明。

`/docs?p=0`：按站点聚合的文档浏览 HTML。这里 p 从 0 开始，分页粒度与搜索不同。

`/terms?p=0`：词项及文档频率浏览 HTML，同样使用从 0 开始的分页。

不要把 HTTP UI 当成已承诺稳定的通用 REST SDK。需要机器可读搜索 API 时，应定义和实现明确 schema、版本与错误语义。

## 7. 启动失败：缺少 JVM jar 或类

先确认 `make build-jvm`，再执行 Websearch build。检查业务 jar、通用网关 jar、classpath 与 jieba 词典资源。业务源码存在不代表 jar 已重新构建。

容器中检查挂载点，远端检查 node-root，宿主包检查 runtime 树。构建机 `~/.m2` 的绝对路径不能直接当成另一台机器的运行依赖。

## 8. 启动失败：Ray 或 jieba 不可用

在启动所使用的同一个 shell 执行 `python3 -c 'import ray, jieba'`。检查 venv 是否激活、Python 是否是支持版本、Ray wheel 是否适合平台、依赖是否完整。

不要只在另一个终端导入成功就认为启动器也用了那个解释器。容器镜像使用独立锁定依赖，宿主 pip 安装不改变容器内容。

## 9. 注册超时或连接拒绝

确认应用监听已建立、网关进程仍活着、APP_IP 是网关可达地址、端口与防火墙正确、节点身份符合预期。`0.0.0.0` 是监听通配地址，不应作为跨机目标地址。

检查是否混淆 Web 端口与 Wire 注册端口；浏览器端口不是网关握手入口。serve-only 只需要 JVM，不应等待不存在的其他角色。

## 10. 页面能打开但搜不到内容

先查 `/stats` 文档数，再看 `/docs` 和 `/terms`，再查抓取日志及语料 HTTP 日志。判断是没抓到、robots 拒绝、编码/抽取失败、词被过滤、索引未提交还是查询分词不同。

确认访问的是本次 READY 地址，数据目录不是空的新目录。不要仅通过延长 sleep 等待一个已经退出的抓取器。

自然语言单字可能被过滤，脚本渲染正文可能没有被抽取。先用第一章受控语料排除网络和网页差异，再排查目标网站。

## 11. 本机 URL 被拒绝

这是默认目标安全策略的预期行为。受控实验显式传 `--crawl-origin http://127.0.0.1:18080`，且 seed 协议和端口完全匹配。

不要把所有私网限制删掉，也不要用代理把目标绕过去。需要抓企业内网时应逐项设计授权 origin、部署网络和访问控制，并验证重定向不能越界。

## 12. --keep 没有更新修改过的网页

keep 保留发现集合，已见 URL 不保证再次抓取。这不是通用 freshness 调度器。可在新目录冷启动对比，或开发有版本/期限的重抓机制，并验证它与任务日志、ID 和文档替换配合。

## 13. 重启后索引消失

先检查是否误用了不带 keep 的普通抓取、启动器是否选择了新的运行目录、JVM WS_DATA/index-data 是否变化、容器是否删除了卷。

不要立即重复启动更多实例。如果是路径配错，先停止并成套保护已有目录，再恢复正确绑定。若已明确执行冷重置，不能靠修改去重文件恢复被替换的索引。

## 14. 日志说已落盘，但退出仍失败

落盘之后还可能发生组件退休、HTTP 排空或网关回收失败。保留所有错误，检查最终退出码和 result；不能截取一行成功日志作为本次完整运行成功的依据。

反过来，落盘请求超时不意味着磁盘一定没写。继续处理前按第七章验证检查点，不要盲目提交不幂等的增量。

## 15. Bad payload、未知类型或确认数量错误

核对 Rust 与对端是否使用同版本制品，type key 是否一致，整数宽度和小端是否一致，字符串长度是否按 UTF-8 字节计算，是否有尾部字节。

错误回复应导致显式失败。不要把错误转为空 Vec、忽略不认识的字段或接受任意 ACK 数量来“提高容错”；那可能把协议错误变成静默数据损坏。

## 16. 数据锁、摘要或历史错误

依次检查是否有并发实例、Rust/JVM 是否配对、备份是否成套、是否降级读取新格式、是否手工移动或改写数据。保存原始文件及版本信息。

这些错误不是建议用户删除 lock、journal 或最新 segment 的提示。只有明确接受丢弃旧状态时，才选择新的数据目录冷启动。

## 17. 当前能力边界速查

- 真实支持：跨 Erlang/Ray/JVM 的业务请求、Rust 编排、HTTP 抓取、分词、完整索引与搜索、检查点恢复、清单接线及拥有资源的生命周期处理。
- 需要独立验收：公网网页质量、DNS/网络攻击模型、真实跨机发布、容器平台、文件系统断电行为和高负载性能。
- 不能从本 demo 推断：生产认证/TLS、全局 exactly-once、任意节点接管、复制共识、全网分片搜索、完整浏览器渲染或严格逐 origin 限速。

## 18. 提交一个有用的问题报告

提供源码 revision、平台/架构、Rust/Java/OTP/Python/Ray 版本、准确命令、运行模式、实际端口、WS_RUN_DIR、退出码、最小语料和可重现步骤。涉及恢复时注明冷启动/keep/serve-only、两个数据根和最后已知检查点。

不要在公开问题中附访问凭据、敏感网页内容或不必要的内网地址。保留原始证据用于本地排查，并尽量以第一章的小语料复现。
