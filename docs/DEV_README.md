## 每份 DEV 文档的强制结构（模板）

1. **范围与红线**——本阶段做什么、不做什么（防范围蔓延，04 R8）
2. **任务分解**——与 TECH_DESIGN 的 WBS 对齐，含估算与依赖顺序
3. **逐模块施工图**——文件 → 类型/函数签名（可直接编译的 Rust）→ 行为规约 → 测试义务
4. **集成锚点**——与既有代码的精确接口（真实文件/行号/签名，随 master 演进重核）
5. **测试矩阵与 DoD**——测试文件清单 + 门禁值 + 验收命令
6. **实现注意事项**——设计文档没有明说但实现会踩的坑（POC 已踩过的直接给出解法）

## 开发流程约定

```
POC 已实证的部分（帧/TCP/语义）→ 直接按 DEV 文档施工，不需重新论证
DEV 施工中发现设计缺口 → 先在 TECH_DESIGN 补 ADR/条款 → 再改 DEV → 最后写码（文档先行铁律）
每完成一个 T 任务 → 跑该任务对应测试义务 → 全绿才进下一任务（小步快走）
```
