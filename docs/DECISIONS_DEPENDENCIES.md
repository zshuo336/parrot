# Parrot 依赖与中间件选型决策档

> 状态：**活文档** · 基准 2026-10-04 · 上位约束：[07 §14.6 E5.1 依赖选型铁律](./TECH_DESIGN_07_异构联邦协议设计.md)
> 规则：**任何新增第三方依赖必须先在此留档再进 Cargo.toml**（PR 必附本档 diff）。三问：① 业界是否有久经考验的库（生产验证 ≥3 年/头部背书）→ 优先用；② 场景是否匹配（性能预算 07 §12/嵌入约束/许可证/依赖传递面）→ 不匹配换或自研；③ 自研须标注原因与"业界库出现时的迁移路径"。

## 2. 自研裁定（无库可用或场景不匹配）

| 组件 | 自研原因 | 规模约束 | 替换路径 |
|---|---|---|---|
| **Raft（DirectoryStore 内嵌）** | ① 现有库（raft-rs/openraft）面向通用 KV 复制，与 Directory 单一职责（逻辑地址→端点表，万级条目、读极重写极轻）不匹配；② 07 §6.4 控制面自举要求 Raft 与 actor 生命周期同体（候选者/领导者即 actor 角色）；③ 自研范围严格限定：日志复制 + 选主，不通用化 | est. 1.5k 行；jepsen 式验证（E1.8 测试金字塔）；性能门禁（§12） | openraft 若演化出 actor 同体嵌入模式可评估替换 |
| **SWIM（06 §2.1）** | 成员表即路由表的同体设计（成员传播与路由共享一份数据），外部 membership 库做不到；参数（probe 250ms/间接探活 k=5）与电信档 E3 联动 | 06 §2.1 定稿 + POC p2 实证 | 无业界同构库；swim-rs 语义过重不匹配 |
| **心跳/重连退避** | ~100 行定时器逻辑，引库反增依赖面 | 05 §2.2 | 无需替换 |
| **Wire 1.0 帧编解码** | 协议本体（28B 头/TLV 握手/结构化错误），不可能用外部库 | 四语言 golden vectors 锁定 | 协议本体不可替换 |

## 3. 明确否决记录

| 提案 | 否决理由 | 日期 |
|---|---|---|
| etcd/consul 进核心（目录服务） | 04 §7.1：外部依赖违背控制面自举（07 §6.4/X12） | 2026-10-02 |
| gRPC 进数据面 | 延迟 ~300µs-1ms 不达 LAN ask <150µs 预算（04 §5）；只允许管理面插件 | 2026-10-02 |
| MQTT 作为底层协议 | 07 §4.5 X11：broker 中心拓扑与 SWIM 冲突、无 cid 配对语义、pub/sub ≠ 点对点寻址、QoS1×ask 重试重复放大 | 2026-10-04 |
| 通用 Raft 库塞 DirectoryStore | E5.1 场景不匹配（见上表） | 2026-10-04 |
| 进程内 JVM/Python 互通 | "跨语言互通的正解是协议不是指针"（04 §9，永久否决） | 2026-10-02 |

## 4. 变更流程

1. PR 标题带 `[dep]` 前缀 + 本档 diff。
2. 评审三问逐条回答（业界库调研 ≥2 个候选对比）。
3. 合并后 `cargo deny` 白名单同步更新（E5.6 G7 门禁）。
